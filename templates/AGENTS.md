# AGENTS.md — {{repo}} 的 agent 工作规则

你在 agentops 流水线里工作。每个会话只负责一个工作项，在自己的独立克隆目录和分支上改动。主仓库和别的克隆你写不了。

## 必须遵守

1. **一项一会话**：只做本会话被派的工作项，不顺手做别的。每个模块同一时刻只开一个会话。
2. **测试只能新增，不能修改已有的**：`tests/`、`fixtures/` 下 main 上已有的文件不要改。需要改已有测试，说明规格有问题：把冲突写在你最后的回复里然后停下，不要再 `ao land`（你改不了工作项文件，流水线会把它转给人）。
3. **不改配置**：`AGENTS.md`、`CLAUDE.md`、`.pipeline.toml`、`justfile`、`.claude/`、`.codex/`、`config/` 由人维护。
4. **删功能要人批**：删除 `src/` 下的文件、删除公开函数，合并时会转给人审批，请在提交说明里写清原因。
5. **只在本分支提交**，不要碰 `main`；不要 push。
6. **做完执行 `ao land`**：提交后运行 `ao land`，把分支送入合并队列。测试结果只认队列自己跑出来的。
7. **不联网、不读留出数据**：`~/data/{{repo}}/holdout/` 是留出数据，会话里读不到也不要试。依赖已预装，不要安装新包。

## 做事顺序

1. 读工作项全文（`ao wi show {{repo}}#<id>`），确认验收条目。
2. 先写测试，再实现。`just test-fast` 快速自检，`just test-all` 完整跑一遍。
3. 提交：`git add -A && git commit -m "<type>: <说明>"`，提交信息第一行用 feat/fix/chore 开头。
4. `ao land`。之后不要再改动分支；如果队列退回，会在工作项里写明原因和提示。
